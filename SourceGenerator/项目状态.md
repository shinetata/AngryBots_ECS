## 📋 项目简介

PGD Jobs SourceGenerator 是一个 C# Source Generator，用于自动生成 PGD 框架的 Job 胶水代码。目标是让开发者使用类似 DOTS `IJobEntity` 的简洁 API，同时内部使用 PGD 框架。

**核心理念**：开发者只需将 `IJobEntity` 改成 `IJobParallel`，其他完全一样！

**开发前提**：
1、不改PGD源码；
2、不改现有基础框架；（IJobifiedSystem.cs、PGDJobExtensions.cs、PGDJobMananger.cs）

### 使用示例

```csharp
// Job 定义（与 DOTS 几乎完全一样）
[BurstCompile]
[WithAll(typeof(MoveForward), typeof(EnemyTag))]
[WithNone(typeof(DeadTag))]
public partial struct MoveForwardJob : IJobParallel
{
    public float dt;
    
    void Execute(in MoveSpeed speed, ref LocalTransform transform)
    {
        transform.Position += dt * speed.Value * math.forward(transform.Rotation);
    }
}

// System（超简洁）
partial class MoveForwardSystem : PGDJobSystemBase
{
    protected override void OnUpdate()
    {
        var job = new MoveForwardJob { dt = Time.DeltaTime };
        job.ScheduleParallel();  // 自动查询、调度、写回、清理！
    }
}

// 或者使用自定义查询（支持多次调度）
partial class CollisionSystem : PGDJobSystemBase
{
    IQuery enemyQuery;
    IQuery playerQuery;
    
    protected override void OnUpdate()
    {
        var job = new CollisionJob { ... };
        job.ScheduleParallel(enemyQuery);   // 检测敌人碰撞
        job.ScheduleParallel(playerQuery);  // 检测玩家碰撞
    }
}
```

**代码量对比**：
- **原始 PGD Job 代码**: ~100+ 行 (手动管理 NativeArray、回写、清理)
- **现在**: ~15 行 (仅业务逻辑)
- **减少**: ~85%

## 🐛 截至目前解决的问题

### 1. 静态字段数据竞争 (2025-10-22)

**问题**：
- 多次调用 `ScheduleParallel()` 时，静态字段 `s_healthArray` 被覆盖
- 导致多个 Job 访问同一数组，触发 `InvalidOperationException`

**解决方案**：
- 改用局部变量 + 闭包捕获
- 每次调用创建独立的 `NativeArray`，通过闭包传递到回调

**效果**：✅ 多个 Job 可以安全并发执行

---

### 2. 依赖链断裂 (2025-10-22)

**问题**：
- 每个 Job 都使用初始依赖 `CurrentDependency`
- 后续 Job 没有等待前一个 Job 完成，导致并发数据竞争

**解决方案**：
- 拆分 `RegisterJob` 为 `UpdateDependency` + `RegisterCallbacks`
- Schedule 后立即调用 `UpdateDependency(handle)`
- 下一个 Job 自动获取更新后的依赖

**效果**：✅ 依赖链正确传递，Job 顺序执行

---

### 3. 内存分配器问题 (2025-10-22)

**问题**：
- 使用 `Allocator.TempJob`（最多 4 帧）
- Job 在 `FixedUpdate` 中调度，可能跨越 5+ 帧
- 触发 `JobTempAlloc` 内存泄漏警告

**解决方案**：
- 改用 `Allocator.Persistent`
- 在 `onDispose` 回调中正确释放

**效果**：✅ 不再有内存泄漏警告

---

### 4. 手动 Dispose 时机错误 (2025-10-22)

**问题**：
- 在 Job 调度后立即手动 Dispose NativeArray
- Job 还在运行中，访问已释放内存
- 触发 `InvalidOperationException`

**解决方案**：
- 移除手动 Dispose 调用
- 使用 `[DeallocateOnJobCompletion]` 或在回调中释放

**效果**：✅ 异步 Job 安全访问数据

---

### 5. 自定义查询支持 (2025-10-22)

**问题**：
- 某些场景需要多次使用同一个 Job 处理不同实体集合
- 例如：碰撞检测需要分别处理敌人和玩家

**解决方案**：
- 添加 `ScheduleParallel(IQuery query)` 重载
- 支持查询缓存和多次调度

**效果**：✅ 更灵活，与 DOTS 用法一致

---

### 6. Query 性能优化 (2025-10-22)

**问题**：
- Query 在每次 `OnUpdate` 调用时都会重复构建
- 每帧都创建新的 Query 对象，影响性能
- 应该在 `OnAddWorld` 或首次使用时构建，然后缓存复用

**解决方案**：
- 在扩展类中添加 `[ThreadStatic] static IQuery s_cachedQuery` 缓存字段
- 生成 `GetOrCreateQuery(IECSWorld world)` 方法实现延迟初始化
- 首次调用时构建 Query 并缓存，后续直接使用缓存
- 使用 ThreadStatic 确保多线程安全

**代码变化**：
```csharp
// 之前：每次调用都构建 Query
public static void ScheduleParallel(this ref MyJob job)
{
    var world = PGDJobSystemBase.CurrentWorld;
    var query = world.BuildHybridQuery();  // ❌ 每帧都创建
    query = query.WithAllComponents(...);
    // ...
}

// 之后：首次构建，后续复用
[ThreadStatic]
private static IQuery s_cachedQuery;

private static IQuery GetOrCreateQuery(IECSWorld world)
{
    if (s_cachedQuery != null) return s_cachedQuery;  // ✅ 直接返回缓存
    
    // 首次使用时构建
    var query = world.BuildHybridQuery();
    query = query.WithAllComponents(...);
    s_cachedQuery = query;  // 缓存
    return s_cachedQuery;
}

public static void ScheduleParallel(this ref MyJob job)
{
    var world = PGDJobSystemBase.CurrentWorld;
    var query = GetOrCreateQuery(world);  // ✅ 使用缓存
    // ...
}
```

**效果**：✅ 显著减少每帧的 Query 构建开销，提升性能

### 7. TempJob 分配器未更新 (2025-10-23)

**问题**：
- 虽然在项目状态文档中记录了应该使用 `Allocator.Persistent`
- 但是 `Constants.cs` 中 `TempJobAllocator` 仍然是 `"TempJob"`
- 导致生成的代码继续使用 `TempJob` 分配器
- 触发内存泄漏警告和 NativeArray 过早释放错误

**解决方案**：
- 将 `Constants.cs` 第215行的值从 `"TempJob"` 改为 `"Persistent"`
- 重新编译 DLL 并部署到 Unity 项目

**效果**：✅ 修复内存分配器问题，生成的代码现在使用 Persistent 分配器

## 🎯 技术亮点

### 1. 零样板代码
- 自动生成所有胶水代码
- 开发者只需写业务逻辑

### 2. 静态上下文传递
- 通过 `[ThreadStatic]` 安全传递当前 System 上下文
- 生成的代码自动获取 `CurrentWorld` 和 `CurrentDependency`

### 3. 局部变量 + 闭包
- 每次调用创建独立的数据
- 通过闭包捕获到回调，避免数据竞争

### 4. 自动依赖链管理
- Schedule 后立即更新依赖
- 后续 Job 自动等待前一个 Job 完成

### 5. Query 缓存机制
- 使用 ThreadStatic 静态字段缓存 Query
- 延迟初始化（首次使用时构建）
- 避免每帧重复创建 Query，显著提升性能

## 🚀 快速开始

### 1. 编译 Source Generator

```bash
cd SourceGenerator
dotnet build -c Release
```

### 2. 部署到 Unity

```bash
copy bin\Release\netstandard2.0\PGD.Jobs.SourceGenerator.dll ..\AngryDOTS\Assets\Plugins\PGD\Analyzers\
```

### 3. 编写 Job

```csharp
[BurstCompile]
public partial struct MyJob : IJobParallel
{
    void Execute(ref MyComponent component)
    {
        // 业务逻辑
    }
}
```

### 4. 在 System 中调度

```csharp
partial class MySystem : PGDJobSystemBase
{
    protected override void OnUpdate()
    {
        var job = new MyJob();
        job.ScheduleParallel();
    }
}
```
